# Reusing assets: the library

Reference for the `an` skill (`../SKILL.md`: the index and the essentials).

## Reusing assets: the library (`an library`)

Assets outlive their videos in a **library** (ADR 0005): one per package, at `~/.local/share/an` (core) or a genre's own root such as `~/.local/share/cutan` (cut-out characters, props and stages go there: `--package cutan`), overridable with `AN_HOME` / `CUTAN_HOME` or `--root`. Never keep reusable assets in a session folder or a repository; publish them. Every library this machine has ever written is recorded in a registry that no environment variable moves, and every statement a library makes about a file's bytes is remembered there too, so private study material binds every other library wherever it sits — even after the library is moved or deleted. A library written at a custom `--root` by an `an` older than that registry is recorded on its next publish, or by `an.library.api.reindex(open_library(<pkg>, root=<root>))`. The registry is per machine: a study library shared between machines (Dropbox) must be published to, or reindexed, once on each. Never delete `~/.local/share/an/registry/` wholesale (it is the only memory of a library moved or kept at a custom root); prune it. Agent-made projects default to `<root>/projects/<project_id>/` (`an init <id> --id --genre <genre>`, `an.library.project_dir`).

- **Publish** a finished asset folder (as it sits in a project): `an library publish assets/characters/alice character.alice-reiniger --package cutan --style reiniger --family alice --origin carved --license all-rights-reserved-private-study --provider "<film>"`. Ids are `<kind>.<slug>`; a different look of the same character is a sibling id in the same `--family`, not a folder. Publishing unchanged content makes no new version; an edit makes `v002`. Give provenance (`--license`/`--provider`, or `source` in the descriptor): without it the asset is `unknown`, which is never publishable. A declared licence counts beside the descriptor's own source, the previous version's, and whatever any library on this machine says about the same file bytes. Copying carved parts into a new asset keeps them private. Label carved parts per file when one character mixes carved and drawn art: `--license cc0-1.0 --provider <you> --license-part 'parts/head_*.png=all-rights-reserved-private-study,provider=<film>'` (repeatable; `*` stays in one folder, `**` crosses; a part whose class differs from the asset's names its own `provider=`) states the heads private and every other file with the asset's label, so the drawn parts stay free. A per-file label, or a per-part `source` in the descriptor, never relaxes what the bytes already carry (an earlier version's statement, a parent's, the same bytes at another path): a freer one is **kept and reported as a rights conflict**, the stricter one binds, and the publish says so with a warning (an#357: inform, don't block). `an library show`, `an library sheet`, `an credits` and `an validate` list each conflict beside the stricter label; `--strict-assets` (on `an library publish`/`promote`, `an validate`, `an render`) refuses instead. A per-part or per-file label on bytes an earlier version left unlabelled is no conflict: it labels them. A relicence resolves a conflict deliberately, and per-file labels stricter than the relicence keep binding. `an library reindex --package <lib> --dry-run` lists what a rebuild of a library's rights index would restate, writing nothing. A character from `an character new` is stamped with its source — the factory's own `cc0` work, or DiceBear's licence for a DiceBear head — on the descriptor and on every part, each pinned to the bytes it describes, so it publishes with no `--license` — even when an older, unlabelled asset holds the same bytes: the factory records what it draws, and that silence does not bind them (a private statement still does). A stamp in a descriptor proves nothing by itself: only bytes the factory provably drew count as its work — this machine's record says so, or (for a character drawn on another machine) the factory re-draws the same bytes from the recipe it records in the descriptor — so stamping a carved part (by hand or with `stamp_factory_parts`) leaves it `unknown`: label it with `--license` instead. A DiceBear head is never re-drawn (it came from the network). A stamp, or a label carried over from an earlier version, speaks only for the bytes it saw: a part re-drawn or re-carved since, or a file added, is `unknown` until you label it (`--license`/`--provider` on that publish, or a per-part source with the file's `sha256`). If you forgot, later versions inherit the gap even with `--license`; label it with `--license … --provider … --relabel-by <who> --relabel-reason <why>`, which answers the asset's own unlabelled files and sourceless versions — and a file an earlier version held that this one no longer holds, even when another asset holds the same bytes unlabelled (tool output like a `silhouette.png` you since removed) — and relaxes nothing anyone stated (a private licence, a per-part source, a parent, another asset holding the same bytes this version still holds). Relabelling unchanged content makes **no new version**: the label is recorded on the head (append-only, `an library show` lists it in the rights' reasons). When a publish stays `unknown`, the lines after the reasons say what answers each gap — a relabel here; label the parent it derives from; or, when another asset still holds the same file unlabelled, relabel THAT asset first and then repeat this relabel (or drop the file); a relicence for anything someone stated. Do what they say, not a second identical relabel. **Never leave tool output in an asset folder** (`silhouette.png`, `preview.html`, `preview.mp4`): it publishes as unlabelled bytes. In a checked-out copy, the label it came with covers only the files as checked out: `an credits` lists a file edited or added since as UNVERIFIED, as publishing the copy back makes it `unknown` — even when the descriptor also has a source a person wrote, until that source is rewritten. The strictest wins: a new version or a `cc0` label never relaxes private art. Only an explicit relicence relaxes it (`--relicense-by <who> --relicense-reason <why> --license …`), and it is recorded on the version. `--expect-head new` refuses an id that already exists, so a different character is never merged into it.
- **Find** by facets — AND across facets, OR within one (comma-separated): `an library find --package cutan --kind character --style reiniger --affords limbs.legs,swap.view:side --near`. `--affords` terms are capabilities derived from the rig, never typed by hand: `limbs.legs`, `limbs.arms`, `swap.view` (`:side`, `:back`, …), `face.mouth` (`:rhubarb9`); an unknown name is refused with the close ones. Whether a character can walk on legs is `limbs.legs` (every character walks: a legless one glides). `--near` lists what nearly fits with the missing capability and its remedy (e.g. `an character add-views`), and a factory character curated for another style (its colours are role-tagged, so a StylePack recolours it at render: `style_pack:` in the scene's meta, the an-style skill). No command restyles a published asset, and a recolour never changes a build — a style needing another build (South Park's `squat`) needs a new character. `--rights publishable` excludes private and unknown assets. `an library vocabulary` lists every facet value and capability, counted exactly as `find` sees them (rights recomputed; retired assets under `hidden`): map the director's words onto those terms, and record the mapping in `.an/decisions.jsonl`.
- **Check out** into a project: `an library checkout <dir> cutan:character.alice-reiniger@v002` (the `cutan:` prefix selects the library; no `--package` needed). The files land in the project's own store (`assets/characters/alice-reiniger/`), byte for byte, with the pin in `assets.lock.json`; the command prints the `yaml entities` line to cast it (`library: "cutan:…@v002"` beside the usual `ref`). The copy carries its rights: `an credits` and the render's private-study warning see private material exactly as in the library. Editing the checked-out copy forks it (a re-checkout then refuses without `--overwrite`; `an validate` reports it as `info`); `an library publish` of that folder sends the edit back as a new version derived from the one checked out. A character (or environment) made in the project and just published is linked by checking it out into the same project (`publish` prints that command): the unedited folder it came from is found under its own key (`characters/alice`, even for `character.alice-reiniger`) and pinned, never copied beside it; no `--overwrite`. **`assets.lock.json` is the record of which version the project holds**; the scene's `library:` must say the same, and `an validate` warns when it does not — to move a project to a newer version of an asset it already holds, check it out with `--upgrade` (`an library checkout <dir> cutan:character.alice-reiniger@v003 --upgrade`): the entry pinned to the older version is updated in place and its pin moves — never a second copy beside it; without the flag the command refuses and says so, and an entry you edited since refuses either way (publish it first). `an library publish` of a project folder prints the exact command, `--key` and `--upgrade` included. Then update the `library:` line `an validate` names. Never hand-type `@latest` into a scene: it is refused; the checkout prints the pinned line.
- **Kits** (a style's StylePack, voice documents, environment, props and cast as one versioned set): `an library kit <library> kit.<slug> <ref>,<ref>… [--key-for ref=key,…]` publishes one, pinning every member to its current version; `an library checkout <dir> kit.<slug>` (or `an.library.checkout_kit`) checks out all members, each pinned in `assets.lock.json`, and records the kit under the lockfile's `kits` section. `--only <key>,…` (or `--skip`) checks out just those members, named by the key they land under or by asset id (an#400): take a style kit's pack and narrator without its cast. A voice document cloned from a real person's voice is private: publish it with that source (`--license all-rights-reserved`), so `an credits` and `an library show` say so and no public kit carries it as free.
- A kit refuses a missing member or a nested kit before writing anything, and its rights are its own document's: each member keeps the rights it carries at check-out. Plain `checkout` of a kit ref refuses and points at `checkout_kit`.
- **Show** one asset: `an library show cutan:character.alice-reiniger` (versions, rights with reasons, affordances). **To inspect an asset without checking it out** (an#453): `an library show <ref> --json-out` prints the whole record and version, the asset's descriptor included (`version.doc`: an environment's planes, a prop's rig), and `an library sheet <ref>` draws it; a check-out to read one file pins the asset in `assets.lock.json` and lists it in `an credits` until you remove it.
- **Retire** a dead id: `an library retire cutan:character.alice --by <who> --reason <why>`. It is recorded on the record (`status: retired`, with who and why in `status_history`), hidden from `find` and `vocabulary` (`find --status retired` lists it), and never deleted: its versions stay readable, so a project pinned to one still checks it out, and what it says about its bytes still binds. Publishing into a retired id is refused unless the publish passes `--status draft` (or another status) to revive it. Retiring relaxes nothing: an `unknown` asset's bytes stay `unknown` for every other asset holding them.
- **Promote** an asset to the core library so another genre can reuse it: `an library promote cutan:character.x`. Private and unknown material is refused unless `--allow-restricted`: carved study material stays where it is. If the core library already has an unrelated asset with that id, pass `--as-id`.

- **Crediting your own art** (an#452): `an credits` lists a file it cannot vouch for as UNVERIFIED with `license=None`: a hand-drawn plane, a part you added, or a factory part you redrew (the factory's stamp pins the bytes it drew, so a redrawn part loses it). Give that file its own source, pinned to its bytes:
  ```python
  import hashlib, json
  from pathlib import Path
  from an.ir.assets import AssetSource


  def mine(file: Path) -> dict:  # your own work, pinned to these bytes
      sha = hashlib.sha256(file.read_bytes()).hexdigest()
      return AssetSource(
          provider="<you>", author="<you>", license="cc0-1.0", sha256=sha
      ).model_dump(mode="json", exclude_none=True)


  d = Path("assets/characters/ned")
  doc = json.loads((d / "character.json").read_text())
  for slot in ("arm_r", "fore_r"):  # a part: the attachment's `source`
      for att in doc["skins"]["default"]["slots"][slot].values():
          att["source"] = mine(d / att["path"])
  (d / "character.json").write_text(json.dumps(doc, indent=2))
  e = Path("assets/environments/studio")
  env = json.loads((e / "meta.json").read_text())
  for plane in env["planes"]:  # a plane: the plane's `source`
      if plane["name"] in ("wall", "skyline"):
          plane["source"] = mine(e / plane["art"]["src"])
  (e / "meta.json").write_text(json.dumps(env, indent=2))
  ```
  Use your real licence (`all-rights-reserved` keeps it out of anything published). Re-run it after you redraw the file: a source pinned to old bytes speaks for nothing. `an credits <dir>` then lists the files under their licence.

Python: `from an.library import open_library, search_path, publish_dir, find, checkout` — the same functions. `an credits <dir>` lists what `an` made itself (factory characters, synthesized sounds) apart from third-party work, the plates an environment's source covers (a plate in an environment with no source is UNVERIFIED), and synthesized speech per voice — provider, voice and model, read from the voice document; it is UNVERIFIED until the voice document declares the provider's terms as its `source`. The licence code for TTS output is the provider's terms for the USER's account — **ask the user which plan their account is on; never write the paid-plan code without their answer, and if unsure leave the voice's `source` out (UNVERIFIED)**: for ElevenLabs `{"provider": "elevenlabs", "license": "elevenlabs-paid-plan"}` on a paid plan (commercial use, nothing owed: listed as no attribution required) or `"elevenlabs-free-plan"` on the free plan (non-commercial use only and a credit to ElevenLabs is owed: listed under NON-COMMERCIAL USE ONLY with its credit, fine in a personal video, never in a monetised, sponsored or client one — the same class as a CC BY-NC sound or picture); a longer code starting with one of them (`elevenlabs-paid-plan-creator`) counts too. Terms count only for the provider that spoke the line, never another provider's (`an.ir.assets.PROVIDER_TERMS`). The first publish on a machine whose registry is missing says which case it is: a new registry (no library holds an asset), or a lost one, rebuilt from the libraries discoverable now (their statements are remembered again; only a library at a custom root not discoverable now needs a `reindex`).
