# `an` — As-Built Architecture

> **What this is.** A snapshot of the system as it exists in the repo today, intended as the canonical reference for both human contributors and AI agents working in `an`. The seven research reports next to this file (`report 0...`, `report 1...`, etc.) describe the *design space*; this doc describes *what was actually built*. When the two disagree, the code is authoritative — fix this doc.
>
> **This is the only capability map.** The capability table lives in §0 below and nowhere else (`CLAUDE.md` deliberately carries none). Add a row to §0 when a capability ships.
>
> Currency: written 2026-05-02, after Phase 10 (iterate loop); §0 and §10 refreshed 2026-09-29; §0 again 2026-09-30 (three times). Update on each substantive change.

## 0a. Core and genre (since the `cutan` move, an#225)

## 1. The story in 30 seconds

You write a `scene.md`. You run `an render <dir>`. An mp4 lands in `output/main.mp4` with audible dialogue, a sky/grass background, two distinct cartoon characters, animated mouths over real ElevenLabs speech aligned by Whisper word-timestamps, eye-blinks, faces driven by the expression solver (each line's `[emotion]`, or an `expression` action — brows, lids, mouth form, and the pupils' gaze with ambient saccades), and a slow camera push-in.

You say `an iterate <dir> "make Maya's response more affectionate"`. Claude (Opus 4.7) returns surgical JSON patches against the IR, validates them against the schema, persists, and invalidates only the affected shot's cache so the next render only redoes that shot.

Both flows pass through the same Scene IR — the single source of truth.

---

## 2. Three-layer IR (the architectural pillar)

Information flows downward. Verification feedback flows upward. Render Code is disposable.

```
Narrative Layer  scene.md                ← human-edited markdown (yaml meta, yaml shot, yaml entities, yaml actions, dialogue)
                       ↕ (an sync — newer-mtime wins, equalize on write)
Scene Graph      ir/scene.json           ← Pydantic-validated, the SSOT
                       ↓ (an.adapters.cutout.compile_shot)
Render Code      cutout JSON for JS      ← regenerated per render, never edited
                       ↓ (an.stage.render — Playwright + ffmpeg)
                  output/main.mp4
```

The `iterate` loop closes the cycle: free-text → Claude → patches against `ir/scene.json` → re-render only affected shots.

## 4. The six `Protocol`s and their implementations

| Protocol | Purpose | Implementations |
|---|---|---|
| `Renderer` | per-shot mp4 production | `CutoutRenderer` (real; a `FrameStageRenderer` over the stage engine since an#247), `ManimRenderer` (opaque-source shots via manimkit; owns its clock — `measure_duration`), `RemotionRenderer` (skeleton), `WhiteboardRenderer` (stub) |
| `Engine` (an#247) | a seekable engine the core drives frame by frame (`frame_stage_renderer(engine)` → `Renderer`); time-driven or state-driven, capabilities read from members | `StageEngine` (`an/stage/render.py`; `an.stage` next); the live tier is declared only |
| `TTSProvider` | text → audio | `OfflineTTS` (silent placeholder), `ElevenLabsTTS` (real, needs `ELEVEN_API_KEY`) |
| `LipSyncProvider` | audio → viseme track (+ `words` when the provider has them, an#96) | `OfflineLipSync` (char-distribution), `WhisperLipSync` (word-aligned, needs `faster-whisper`), `RhubarbLipSync` (phoneme-aligned, needs `rhubarb` binary; recognizer follows the language). The compiler runs `cutan/compile/coarticulate.py` over the raw track before emission (an#97): merge, suppress sub-frame tongue shapes, two-frame lead, decay before rest, and a minimum hold that votes |
| `Verifier` | verify IR ± render | `LayoutLintVerifier`, `MediaQualityVerifier`, `VisionLMVerifier`, `HumanInTheLoopVerifier` |

All four protocols are runtime-checkable; new implementations register via factories or `register_renderer(...)`.

## 6. Caching: content-hash everywhere, invalidation by digest

The system caches at every boundary that's expensive to recompute. Cache keys are content hashes — never timestamps, never counters.

| Cache | Key | Computed by |
|---|---|---|
| TTS audio | `_stable_hash({text, voice_id, tts.name})`, plus — only when declared — `effects` (pitch, tempo, `trim_silence` with its resolved parameters and version — an#254), `provider_voice` (an#194), the provider's synthesis `options` (model, settings, seed, audio tags — an#209) and, for one candidate take of a best-of-N line (an#265), `take: i` (i ≥ 1) and `roll: r` (r ≥ 1); a best-of-N line's `audio_ref` is its CHOSEN take's own key | `pipeline.audio_key`, `pipeline._line_request`, `pipeline._load_or_synthesize`, `pipeline._load_or_choose_take` |
| Best-of-N take record | the line's choice key: its request (text, voice, provider, effects, options) + `n` + the scorer's name and config, never its version — the resolution every render reads, not a cache | `pipeline._line_request` / `_load_or_choose_take` → `mall["takes"]` |
| Viseme tracks | `_stable_hash({audio_key, lipsync.name, transcript})`; the sidecar records `audio_sha256`, and a cached track is re-aligned when it is not the audio's digest, or (legacy sidecar) when the audio was produced in this call — the audio key names a request, and a re-synthesized line is different audio (an#289); the scene-level "already done" fast path verifies the same digest and re-stamps the IR from a verified sidecar (`_stamps_match_store`); a legacy sidecar (no digest) is trusted only when its recorded duration is the audio's, then gains the digest (`_backfill_digest`) | `pipeline._load_or_align` |
| Shot cache (an#242, ADR 0004) | `compose_shot_key` over named parts: `renderer`, the keyer's (`compiled` = `scene_contract_sha256`, `textures`, `easings`, `audio`, `runtime`, `knobs`), `environment`, `assets` (the entries the shot read, an#316), `project` (the lockfile) — never `shot.id` | `an.build.ShotCache` via `render.render(incremental=…)`; cut-out keyer `an.adapters.cutout.cache_key` |
| Manim shot (an#279) | shot key: `source` (every file of the staged sources folder), `manim` (entry, scene, Manim + manimkit versions, quality, LaTeX mode), `knobs` (fps, size, background, encode argv), `audio` (muxed lines + frame count), `code` (adapter + `an.media` sinks), `reads` (what the files the picture's render read outside the sources folder hold now, an#291); environment = Manim's package stack, full ffmpeg banner, LaTeX/dvisvgm, font set, ISA. **Picture key** (the `measurements` + `pictures` stores) = `source` + `manim` only; a stored picture is reused only while its recorded read trace holds | `an.adapters.manim_adapter.manim_shot_inputs` / `picture_inputs` / `manim_environment` |
| Per-shot mp4 ARCHIVE | `shot.id` — an archive of the latest render, not a cache | `render._archive_shot` — written, never read |
| Final mp4 | `output_name` | `render.render` |
| Anthropic prompt cache | scene JSON + schema hint (`cache_control: ephemeral`) | `iterate._call_claude` |

The hash is stamped onto the IR (`Dialogue.audio_ref`, `Dialogue.viseme_ref`) so the orchestrator can detect provider changes — when you swap `--tts elevenlabs` for the offline default, the new expected hash mismatches the stored one, triggering re-synthesis without an explicit force flag.

Invalidation is **by digest, never by deletion** (ADR 0004 decision 6): a changed input is a different key, and an entry nobody asks for again simply stays until `an cache gc` removes it (an#274; below). The audio keys have no version field; the shot key carries `SHOT_KEY_IMPL_VERSION`, bumped when the key's composition changes or a renderer changes its output in a way none of its parts records.

**The shot cache (an#242).** `render_project` (and so `an render`, `orchestrate`) computes each shot's key before any browser launches and renders only the misses. What the key is built from, and why each part:

- **The compiled document**, digested exactly as the bench's `scene_contract_sha256` — the early cutoff: an edit that compiles to the same document re-renders nothing. The keyer calls `compile_shot` with the same arguments `CutoutRenderer.render` does (pinned against it by a test), so a miss compiles twice (milliseconds; measured in the PR).
- **Texture bytes, SVG included**, resolved the way `_stage_scene_assets` stages them. SVG art keeps a plain alias in the document (raster art carries its digest since an#211), so an SVG edited in place moves only this part. Key only: the wire shape and `scene_contract_sha256` do not move, so bench comparability is untouched — the contract hash and the cache key are distinct and must not be conflated.
- **Easing versions** for every registered name the document's keyframes carry (an#239 item 1): a replacement curve must raise its version, and the key sees it.
- **Muxed audio**: each muxed line's `audio_ref`, `viseme_ref`, start and the sha256 of the bytes the store returns, plus the picture length the mux cuts to.
- **`runtime_sha256`** and **every render knob, resolved** (`pix_fmt=None` → the module default *at call time*, which is what the bench's levers rebind), plus the pinned Chromium/x264 argv, the scale filter and the faststart flags.
- **The render path's Python source** (`code`): a digest of every module `CutoutRenderer.render` reaches — capture, canvas readback, supersample and shutter resolves, the audio mux — found by walking imports from `an.stage.render` (compile-side modules excluded, with the reason, because their output is the `compiled` part). The Python twin of `runtime_sha256`: an `an` upgrade that changes how a shot is encoded (an#195 did) re-renders every shot. No hand-bumped constant decides it.
- **The renderer's registered identity**: its class and its keyer by qualified name. A keyer is bound to one renderer class; a subclass or a test double that borrows the name `"cutout"` is never cached. Registrations refuse a silent replacement; an input read outside the document joins additively (`register_shot_key_part`).
- **A separate environment digest** — Chromium build and WebGL identity (one browser launch), Playwright, the FULL `ffmpeg -version` (every library and the configure line — the first line does not change when a dynamically linked x264 is upgraded) and the x264 build that actually encodes (one 16x16 encode, its SEI read back, the bench's own key), the ISA and OS family, Pillow and numpy; once per process per renderer, so a long-lived host does not see a mid-process upgrade. A machine change invalidates renders without pretending the content changed.
- **Fonts, when SVG art draws text.** Text units are outlined in Python and travel inline in the document, but an SVG part may carry its own `<text>`, which Chromium draws with the machine's fonts: a shot that stages such a part gets a `fonts` part (`fc-list`, else the platform font folders' listing).
- **No stat memo decides a key.** Asset bytes and the render path's source are read and hashed on every render (under 10 ms for a whole corpus project); only the import parse of a source file is memoised, keyed on its content hash.
- **The asset entries the shot read** (`assets`, decision 3; an#316). The engine hands the keyer a `RecordingMall` (`an.build.reads`): a view of the mall that notes every entry of an asset store (`PROJECT_ASSET_STORES`) the compile reads — a `[]`, a `get`, an `in` — and every store it lists (iteration or `len`: the whole store, `store/*`). Each read is digested as what the mapping returns plus the entry's files beside it (`<root>/<key>/**`, `<root>/<key>.json`: a prop's sidecar font, a character's parts), and the map `{"store/key": digest}` is kept on the entry (`ShotArtifact.reads`). So an edit to a prop that only `main` places re-renders `main` alone, a sound (mixed into the film by `an.assemble`, never into a shot) re-renders no picture, and an asset nobody reads re-renders nothing. Art the compiler reads by path behind the mapping (gap 3, `_root`) needs no routing first: what reaches the pixels is staged from `assets.textures`, whose bytes are the `textures` part. The texture files are resolved by ONE function, `an.stage.render.texture_source`, which both staging and the key call, so a change to where art is read from (ADR 0005's reference mode) changes both or neither. A keyer claims this with `register_shot_keyer(..., records_reads=True)` (the cut-out one does); one that cannot vouch that its reads go through the mall — Manim runs an opaque source that may open any file (an#291) — gets `ShotCache(fallback=...)` as its `assets` instead, by default every asset in the project (`every_asset_digest`, decision 3's first slice). What EVERY shot depends on is `ShotCache(dependencies=...)`, the `project` part: by default the project-root files in `PROJECT_ROOT_FILES` (`project_dependencies`: the library lockfile `assets.lock.json`, read by path, an#240), so a re-pin re-renders the film, conservatively. `record_reads=False` gives every shot the fallback; `None` for either seam drops its part. An engine built with other seams writes keys `an cache gc` (which recomputes with the defaults) does not reach.
- **Why a shot was not reused** is read off the newest earlier entry of the same shot id (a catalog scan on the first miss; the id finds the entry, it is never a key): `asset changed: props/logo`, else the parts that moved by name (`render settings changed`, `the render environment changed`), else `the shot key's format changed (an upgrade)` when the entry was written under another `SHOT_KEY_IMPL_VERSION` (2 since an#316; recorded on the entry as `key_version`), else `new or changed`. Only the 64-hex mp4 entries are read for it, never parts, frames or roots.

Entries are `lacing.Artifact`s (subclass `ShotArtifact`: `asset_id` = sha256 of the mp4, PROV provenance whose `was_derived_from` lists the part digests, plus the named `inputs` and the `timings`) in a `lacing.ArtifactStore` at `artifacts/shot_cache/{catalog,blobs}/`. An assembled film (transitions, a sound layer) is a concat of video-only segments (an#260, §0): a shot no transition touches needs only its mp4 entry; a shot one touches also needs `<key>.parts.<code>.h<head>.t<tail>` — a stored zip of its body's encode and its window's PNGs, keyed by the window (another neighbour cuts it differently) and by a digest of the code that cuts and encodes it (`an.assemble`, `an.media.{mp4,frames}`), because the renderer's `code` part does not cover `an.assemble`. Measured on `park_bench_cartoon` at 1080p with a 0.5 s dissolve and a bed: warm 1.4 s against 26 s cold (sound only: 0.36 s against 23 s), byte-identical film warm and cold, both parts entries 350 KB against 3.2 MB of PNGs for the two shots. The older whole-frames entry (`<key>.frames`) is written only for a caller that plans with `needs_frames=True` and `ShotCache(cache_frames=True)`; the render loop no longer does, so `--cache-frames` is inert, and `an cache gc` collects old ones. Each blob is checked against its id (its sha256) when read; a mismatch is a miss. A cached render works in its own `.an/render_work/runs/<run>/` (when a run delivers its film it marks itself done and removes every other finished run — done, or whose process is gone — keeping itself as the latest; a run in progress is never touched), so two renders of one project at once never record each other's bytes; a reused shot is materialised in a directory of its own plan (`shot_cache/<index>_<id>/`), so two shots with one key never share files. The pre-cache `artifacts/shots/<shot.id>.mp4` files are never read.

**Garbage collection (an#274, `an.build.gc`; `an cache gc`, `an cache info`).** Every cached render records a *root* (`root.<digest>` in the same catalog, a `ShotArtifact` of role `root` whose `was_derived_from` is the shot keys): the entries a render of output `<name>` of one project (a digest of its resolved path) under one knob set (as passed — `None` is "the scene's own"; with the TTS and lip-sync provider names) on one machine (a digest of host name and hardware address) used; the next such render replaces it. Roots are never collected. An entry is **reachable** if (a) a render of the CURRENT scene would read it — `an.render.cache_entries` runs the render loop's own setup (`_prepare_shots`: burned captions, style pack, film windows) and the engine's own key code (`ShotCache._key`, shared with `plan`), under every knob set any root ever recorded (with its own recorded TTS: `voice`, a name, or none for an instance) and a plain render's (`gc.HYPOTHETICAL_PROFILES`: today's `tts=voice` and the pre-an#305 `tts=offline`), stamping the dialogue from the content-keyed audio and viseme stores exactly as the render's audio pipeline would (`an.audio.pipeline.stamp_from_stores`: the real providers' keys, a read-only view of the stores, and `synthesize`/`align` refusing) — because a `scene.md` edit drops every stamp on re-sync and the next render re-stamps the same audio; a line whose audio or visemes are not in the stores is re-made IN MEMORY when its provider is free and repeatable (`an.audio.pipeline.free_and_repeatable`: it declares `repeatable` and has no `billed_characters` — offline speech, the core's `none` lip-sync; an#311): `cache_entries` puts `InMemoryOverlay`s in front of the audio and visemes stores (`in_memory_audio_mall`), `stamp_from_stores(free_in_memory=True)` runs those providers for real into them, and the keys read the re-made bytes — the stores are never written and no billed provider is called; a knob set under which a line's audio is still not in the stores (a billed or non-repeatable provider: `AudioNotCachedError`) is SKIPPED — that shot has no key until synthesised — and every root recorded under it keeps its entries whatever `--max-age` (an#306); only when the scene can be keyed under no knob set does the collection refuse; a clock-owning renderer's shot (Manim, an#279) is keyed at its MEASURED length, settled inside `_prepare_shots` from the stored measurements only (`settle_durations(render=False)`), so a collection never runs Manim and never keys such a shot at its authored length — or (b) a root names it, which keeps what a render on ANOTHER machine of a synced project used. If (a) cannot be computed, the collection refuses and deletes nothing; it also refuses a cache in which no render of this project has recorded a root, unless `--force`. **Never deleted:** a reachable entry, whatever `--max-size`/`--max-age` say; anything written after the earlier of the collection's start and the start of every live render of the project (`.an/render_work/runs/<run>/.live`, its process alive, no `.done`), less 2 s of slack — so a render's entries are protected from its run's start until its root names them; a blob a kept record names. **A render racing a collection** sees, at worst, a record whose blob vanished — a miss, so the shot renders again: blobs are checked against their sha256 on read, a lookup copies the bytes into the render's own run directory, and records are deleted before blobs. **The renderers' derived stores are collected too** (an#299, `an.build.derived`): a renderer declares them beside its shot keyer with `register_derived_stores(name, DerivedStores(record_store, named_stores, entries, provenance, names))` — the record store (Manim's `measurements`) whose entries NAME the others (`pictures`, `contact_sheets`), `entries(renderer, shot, ctx)` (the record keys a render reads, computed: Manim's picture key), `provenance(render_provenance)` (what a cached shot names) and `names(record_bytes)` (what one record names; `UnreadableRecordError` for bytes it cannot read). A store has one owner (a second claim is refused). `an.render.cache_reach` returns the record keys beside the shot ids (`cache_entries` is its ids). Kept: what the current scene reads under every knob set, what every KEPT shot entry's provenance names (so a root's — another machine's — shots keep their pictures), anything written since the protection horizon, each closed over what its records name. The caps trim unreachable history in UNITS (a record with what it alone names), newest first, against ONE `--max-size` that the shot cache's kept bytes count toward first. Records go first; then the record stores are listed and read again, and a named entry goes only if no record present NOW names it — a render racing the collection writes a record naming an older picture (a content-addressed picture is not rewritten, only touched: `_store_content` refreshes its mtime) and that picture stays; a record that cannot be read stops every named entry from going that run. `--dry-run` deletes nothing (`GcReport.deleted_derived`); `an cache info` reports each store's size and unreachable share (`CacheInfo.derived`).  Deletion is permanent (the files are unlinked in `lacing`'s documented `catalog/`, `blobs/` layout, because `dol.Files` would move them to the OS trash and free nothing). `--max-age D` keeps unreachable entries younger than D and lets older roots stop naming their entries (their knob sets are still recomputed, so the current scene's entries under them stay); `--max-size S` keeps the newest unreachable entries that fit in S.

**For measurement: `render()` is cold by default.** The bench, the golden corpus, the cross-arch capture and the demo builds call `an.render.render`, whose `incremental` defaults to `False`, so their wall times stay real and a lever that rebinds something outside the key (the supersample lever's `_capture_frames`) can never be answered from cache. Only `render_project` defaults to the cache. (an#31's correction — "the per-shot store has no read path, so every render is cold" — still describes `mall["shots"]`, and now describes `render()`; it no longer describes `render_project`.)

## 7. Key invariants to preserve

These are load-bearing. Breaking them breaks the system in subtle ways.

1. **`scene.md` and `ir/scene.json` mtimes are equalized after every store write.** Otherwise `sync` flip-flops between md and json on each load and pipeline-injected state (viseme tracks, audio_refs) gets stripped. Two files of the same age (within `SYNC_MTIME_TOLERANCE_S`) that DISAGREE were edited outside the store (a `cp -r` then a `sed` in one second): `sync` takes `scene.md` and regenerates the JSON with a `SyncTieWarning` (an#412); before, the stale JSON won silently and the next store write reverted the edit (an#411). See `ScenesStore.__setitem__` and `sync()`'s "newer wins" tolerance band.
2. **The synthetic root container in the JS runtime is not indexed.** `compile.py` emits target paths starting with the entity name (`charlie/head/mouth`), not `root/charlie/head/mouth`. The runtime's `animaLoadScene` skips the synthetic root when populating `nodeIndex`.
3. **Multiple characters are spread along x in `_layout_character_positions(n)`.** A previous bug placed every character at (0, 0) so they overlapped. The default spread is 220px; characters with the same `entity.id` between renders keep their position because the spread is index-based.
4. **Composition trees flatten to canonical FlatActions for verification and rendering.** The DSL (`sequence`, `parallel`, …) is for authoring; `flatten()` produces absolute-time `FlatAction`s that downstream stages consume. Don't reason about composition nesting at render time.
5. **`extra="allow"` on every Pydantic IR model.** Forward-compat: an older reader of a newer document survives. The cost: typos in field names don't error.
6. **`anima*` JS API names were renamed to `an*` during the package rename.** `window.anLoadScene`, `anSetTime`, etc. The Python side calls these via `page.evaluate`; both must stay synced.
7. **The ScenesStore's `"main"` key is the only supported key.** Multi-scene projects are a future feature.
8. **A substituted asset is recorded, never merely substituted.** A character whose ref is not in `mall["characters"]` gets the placeholder rig; an environment ref that names neither a store entry nor a built-in preset gets the default backdrop. Both are legitimate — an asset-less project must render — and both used to be *silent*, which is not (an#33). `compile_shot` now appends one `AssetResolutionJSON` per drawable entity to `CutoutSceneJSON.asset_resolution`, warns (`CutoutCompileWarning`) on any `fallback=True`, and raises under `strict_assets=True`. The record is load-bearing rather than decorative: a missing descriptor and a deliberately-procedural character compile to the **same scene tree**, so nothing downstream of the compiler can tell them apart. `strict_assets` threads `an render --strict-assets` → `render_project` → `render` → `RenderContext.strict_assets` → `compile_shot`; `misc/bench/crossarch.py` sets it, because a pixel measurement of the wrong picture is worse than no measurement.
9. **A ledger row's comparability is decided by its provenance, not by its numbers.** Two rows measured on different scenes, or on different x264 builds, are not "one better and one worse" — every metric in them is mutually uninterpretable. Render-side metrics are comparable across machines (pixels are ISA- and OS-invariant at a pinned Chromium build); encode-side metrics are **machine-scoped and must be refused rather than banded**, because a band wide enough to absorb an x264 build change would swallow `flat_field_deviation`'s entire crf18->23 signal. The deciding fields are `scene_contract_sha256`, `environment.encode_side.x264_sei` (verbatim) and `.isa`. Two of the four value states are null and they mean different things: `gated` (the comparison is impossible) is not `unavailable` (the check did not run), and neither is "no change", which is a prediction that can never count.
10. **A verifier that could not run must not report `passed=True`.** `VerificationReport.add` flips `passed` only on `"error"`, so an `info` Finding on a failure path is byte-identical to a clean review — which is how a dead model id, a 500, a refusal and an unparseable reply all came back as "vision LM reported no issues" (an#39). `info` is reserved for *not configured* (no key, no SDK, no render); configured-and-broken reports at `an.verify.vision.FAILURE_SEVERITY`. Relatedly, `_parse_issues` returns `None` for "no verdict" and `[]` for "empty verdict", because collapsing them is what made a refusal indistinguishable from a pass.
11. **The determinism perimeter is observed on every render and enforced by default.** `runtime.js`'s `anDeterminismReport` reports the capture page, whether any PixiJS ticker is running, every node carrying a filter, and the per-entity blink phases; `an/determinism.py::capture_violations` judges — a pure function of that dict, so the rule is testable with no browser. The report lands in `RenderResult.provenance["determinism"]` beside the verbatim Chromium and x264 argv. A breach raises `CutoutRenderError`; `AN_DETERMINISTIC=0` downgrades it to a recorded fact. The three things it watches are deterministic *by accident* today: the app is built `autoStart: false`, nothing attaches a filter, and the capture page is `index.html` while `preview.html` (seven clock calls) is staged into the same directory. **The blink phase is a pure function of the entity NAME** — renaming a corpus character re-phases every blink and moves every pixel metric — which is why the phases are stamped rather than merely correct.

12. **The timing contract is generated, never hand-edited, and a change to a committed sample is a change of the contract.** `an/data/timing/*.json` are written by `python -m an.timing.contract write` from the registries; `tests/test_timing_contract.py` fails on drift (numbers within `1e-9 · max(1, |x|, |y|)`, since transcendental functions may differ in their last bit across maths libraries). A kernel change is gated on four checks, not the contract hashes alone (`scene_contract_sha256` covers the compiled document, not its evaluation): unchanged corpus hashes, the Python/JS parity tests, the pure-pose tests, and the decoded-pixel goldens. The stage evaluates by value type (`kind=None`), exactly as `runtime.js` does, for every target whose entity declares no space; a target whose entity's kind declares one (`meta.entity_spaces`) is evaluated by that space's declared kinds, write groups and the full easing registry, from the definition the compiler embeds (`meta.spaces`) — in `runtime.js` and in `timeline_from_compiled` alike (an#287). For the value-typed rule, easings included: the value-typed rule accepts only `runtime.js`'s six names, and compile (per keyframe) and validate (per tween) refuse any other, so what validates is what the player draws; the default's write groups come from the space named `DFLT_VALUE_TYPED_SPACE` (`stage.node`), resolved by name at call time; the golden vectors' `stage.node` cases are checked under both rules; the declared `stage.node` space gives the same pose on every corpus frame (`tests/test_timing_kernel.py`), which is what makes switching the stage to declared kinds a later, gated step rather than a pixel change hidden in a move. **`ease` is `an`'s quadratic, not CSS `ease`** (spelled `cubic-bezier(0.25, 0.1, 0.25, 1)`, published as `css_import_aliases` in `easing.json`; ADR 0001 decision 10, amended); a front-end importing CSS-named documents must translate it. Registrations carry an owner and only `an`'s reach the contract files, so an installed genre never edits them.

13. **A genre extends the IR by registration, never by an edit to a core dispatch.** `flatten`, `duration_of`, the `scene.md` reader and writer, `an validate` and the compiler find an action kind through `an.genres.registry`, and the schema's union is never rebuilt (ADR 0001 decision 2's ordering trap: `Shot` and its cached validators stay as built). Nothing registers a genre at import time; `an.genres.load()` does (`an.load`, the CLI). An unregistered kind is an error naming the genre that provides it — never a silent drop from `scene.md`, never a bare `TypeError`.

14. **A behaviour that needs structure declares it in the capability registry; it never adds an `if rig has X` branch** (ADR 0002 decision 8). Its method lists `requires` as requirement terms, its aspect's chain ends in a method that requires nothing (checked when the genre registers), and the compiler resolves it through `an.semantic.resolve` on the analyser's profile — the library's facets and the compiler's choice are one derivation. A requested method replaced by a fallback is recorded in `asset_resolution` (`kind: method`), fatal under `--strict-assets`. A vocabulary entry whose meaning changes bumps its version in the same change.

A dialogue line may carry one timing in parentheses — `maya (pause 1.5): …` or `maya (at 3.0): …` — beside or instead of the emotion (an#187); parentheses hold only timing.

The `[emotion]` brackets on dialogue lines are sugar for an `expression` leaf over the line (an#98): `cutan/expression/presets.py` holds the presets (`neutral / happy / sad / angry / surprised / afraid / disgusted / thinking / skeptical / amused`), the face solver `_add_face_clips` in compile.py sums them into one channel per `(node, property)` — brows, lids, and the mouth's `viseme@<form>` set — and an unknown name is a validate error, not a silent neutral.

**A write never regenerates the author's file** (an#275). `ScenesStore.__setitem__` and `sync()` (when the JSON is newer) go through `an.ir.sync.merge_markdown`: if the file already says what the IR says (the same canonical form, `ir_to_markdown(markdown_to_ir(md))`) it is left byte for byte — the common case, a render that only added audio and visemes to the JSON — and otherwise only the title line, the `yaml meta` block, a shot heading, or one of a shot's `shot`/`entities`/`actions`/`dialogue` blocks whose content changed is rewritten (in the writer's block style); a new shot is appended, a removed one dropped with its section, and prose, comments and unknown blocks are never touched. The result is verified to read back as the IR; when it cannot be (an unreadable file, a duplicated shot id) the file is regenerated whole with a `MarkdownMergeWarning`. The mtime equalisation is unchanged: the md's mtime is set even when its bytes are not rewritten.

## 10. What hasn't shipped

This section previously listed four "phases that haven't shipped yet" — real
character art, per-shot parallel rendering, live preview, and asset promotion.
**All four have since shipped** (`svg_sprite` visuals in `compile.py` +
`makeSvgSprite` in `runtime.js`; `an render --parallel auto|N` via
`_resolve_parallel`; `an preview` via `preview_project()`; and promotion as
`cutan.characters.promote` — not `an.assets.promote`, which never existed). They
are described in their own sections above.

What genuinely remains, in rough priority order (each item re-checked against the code on 2026-09-29; the full gap and sharp-edge list is `misc/docs/sharp_edges.md`):

1. **A shot-to-Manim compiler (Manim step 2).** Since an#279 a Manim shot is
   an opaque scene file (step 1); no entity, action or camera of the IR reaches
   Manim. Step 2 — a math-viz genre whose entity and action kinds compile to
   Manim (core study §4.2) — is unstarted design work. Also open on step 1: a
   source from the asset LIBRARY (only the project's `sources` store today), a
   multi-file scene (one file per key), Manim's own per-`play` cache across runs
   (its media dir is per render), and replaying a reused shot's findings.
2. **`ping_pong` has no emitter, and placements cannot override a clip's
   loop.** Both evaluators honour all three `loop_mode`s (`runtime.js`
   `wrapTime`, `clip.py` `_wrap_time`), and since an#7 a `play` of a looping
   descriptor animation compiles to `loop_mode="loop"` (`_resolve_play`) — so
   the old line here, "nothing ever emits a non-default loop_mode", is closed.
   What remains: no compiler path writes `ping_pong`, and `PlacedClipJSON` has
   no `loop_mode` of its own (issue #7's step 2, deferred until clip dedup
   exists; per-instance `__play__{n}` clips make it unnecessary today —
   tracked as an#94).
3. **Lip-sync for face-baked characters.** A descriptor declaring
   `face_overlay: false` (DiceBear avatars; the 0.3.0 migration derives it from
   the old provenance string) has the face baked into the head SVG, so the
   compiler suppresses both the overlay mouth and the viseme channel. Those characters speak without
   moving their mouths. Hand-rigging (see `examples/promote_demo/`) is the
   production path today.
4. **Multi-scene projects.** `"main"` is the only key the scenes store supports.
5. **The default timing is smooth, and the ledger cannot argue otherwise.**
   `step_hz` (an#89) steps authored tweens on demand (`Meta.step_hz` /
   `Shot.step_hz` / `an render --step-hz`), camera and blinks exempt by
   construction. Whether to flip the default to "on twos" is a temporal,
   aesthetic judgement: measured, stepping moves the scene contract hash on
   every scene with a tween, so `bench-compare` refuses a stepped row before
   any family is examined, and outside the comparer the per-frame families
   move with the pose content in both directions — no lever could be
   registered (the `pix_fmt` precedent, one step earlier). Epic #9's Decision
   5 asked for "the ledger and a human A/B agreeing"; the ledger half is
   withdrawn on that measurement. The A/B is the `stepped-timing` demo, with
   its frame strip committed at `misc/docs/step_hz_side_by_side.png` (smooth
   left, 6 Hz right); the flip is a one-line PR that only the maintainer
   makes, and it has not been made.
6. **A real `an validate` for everything the renderer refuses.** The pre-flight
   reports the IR-level refusals (unknown `camera.move`, `narration`; `prop`
   entities stopped being one in an#108, which made them drawable, and
   `_DRAWABLE_ENTITY_KINDS` is pinned equal to the compiler's dispatch by test;
   `play` is resolved against the target's descriptor animations
   since an#7), and since an#109 it no longer duplicates the compiler's camera
   list — both call `an.ir.camera.camera_keys`, so a move that validates cannot
   then raise at compile. It still cannot see rig-level problems: a speaker
   whose character has no head is discovered at compile time. Since an#111 it
   also **warns** when a camera translates over a stage with no depth — the
   render is correct, the whole picture slides, and that is also exactly what a
   flattened parallax looks like.

## 11. Test architecture

Run `pytest -q` for the current count — a number written here only goes stale.
The suite is layered:

- **Doctests** in module docstrings cover the public API of each module (composition flatten times, channel snap semantics, easing endpoints, etc.).
- **Pytest** for cross-cutting checks: store roundtrips, IR migration chaining, sync flip-flop regression, mall conformance, multi-shot concat audio, multi-character render distinct.
- **Live API tests** are gated on an explicit positive opt-in — `AN_LIVE_API_TESTS=1` **and** `CI` unset — not on a key being present. That distinction is the whole point: the previous "skip-if-key-missing" gate was satisfied by every developer machine and every agent session that had sourced a shell profile, so a plain `pytest -q` once made real, billed ElevenLabs calls and reported PASSED. The switch is defined in the **package** (`an/live_api.py`) rather than in `conftest.py`, because the test suite is not the only thing that must refuse to spend unasked: `examples/character_gallery/build.py` reads the same predicate before choosing ElevenLabs (an#63 — it chose on key-presence alone, and an example is the first thing a new user runs, on a clean checkout where the audio cache is cold), and an example cannot import a conftest.
- **The suite is offline and hermetic, and a guard enforces it.** `tests/conftest.py` refuses *and records* non-loopback socket use; `hermetic_browser` does the same at the Playwright layer, because a socket patch cannot see Chromium.
- **Silent discards raise.** Seven places that accepted something and produced nothing now raise typed errors; `an validate` reports the IR-level ones before any money or browser is spent. See `misc/docs/wave1_verification.md` §4.
- **End-to-end render tests** (skip-if-ffmpeg-or-chromium-missing) that produce real mp4s and assert structural properties (audio stream present, frames change, characters distinct).

The project's CI runs the offline subset; a developer machine with all dependencies installed runs the full suite (~70s).

## 14. The asset library (`an.library`)

The persistent, cross-project asset store of ADR 0005 (design: `misc/docs/asset_library_design.md`), first slice (an#234). The mechanism is core and genre-neutral. The character analyser in it is genre code, and it waits here for the genre package (plan P8).

**Where.** One root per package (plan §1 decision 7): `an` uses `~/.local/share/an`, and each genre uses `~/.local/share/<genre>`. `an.library.root.library_root` resolves `root=`, then `<PKG>_HOME`, then `$XDG_DATA_HOME/<pkg>` / `~/.local/share/<pkg>` / `%LOCALAPPDATA%\<pkg>` (vendored; no `config2py`). Under the root sit `library/` (the stores) and `projects/` (agent-made projects, `project_dir(id, package=…)`, default package `an`: the core names no genre. A genre declares the package whose root holds its library and projects (`Genre.library`; the cut-out genre's is `cutan`), read through `an.genres.genre_library`; `an init --id <id> --genre <slug> [--package …]` creates a project there). Nothing is created until the first write. Opening a library whose root is inside a git work tree warns (`LibraryLocationWarning`), and so does checking private material out into one.

**Stores** (`an.library.stores.build_library_mall(root=None, *, package, **overrides)`). Each store is a `dol` codec (`wrap_kvs` + a JSON codec + key transforms) over `LocalFiles`, a byte store with three properties `dol.Files` lacks:
- *atomic*: writes go to a temp file, then `os.replace`;
- *exclusive* creates: `create_only` is a hard link of the finished temp file;
- *contained*: a key resolving outside the store raises `KeyError`.

Every store can be replaced by injection:

| Store | Key | On disk | Invariant (kept under injection) |
|---|---|---|---|
| `records` | `<asset_id>` | `library/records/<asset_id>.json` | curation; mutable |
| `versions` | `<asset_id>@<vNNN>` | `library/versions/<asset_id>/<vNNN>.json` | `WriteOnce`: overwrite and delete raise `VersionExistsError`. When the store offers `create_only` (the folder backend; a conditional put on S3), every write goes through it, so racing publishers cannot both win, and `publish` retries on the next label. |
| `blob_rights` (derived) | `<sha256>` | `library/blob_rights/<aa>/<sha256>.json` | the floor index: one statement per asset about those bytes; rebuildable (`reindex`) |
| `blobs` | `<sha256>` | `library/blobs/<aa>/<sha256>` | `ImmutableBlobs` (a `dol.content` CAS): a key always equals its bytes' hash, and deletion is refused |

A record's `head` only moves forward: it is re-read before writing, and corrected if a racing publisher's late write regressed it. Hard-link-less filesystems fall back to an exclusive open. Keys are validated by the grammars in `an.library.ids` before they become paths: `<kind>.<slug>`, `vNNN`, and `[<library>:]<asset_id>[@vNNN|latest|sha256:<prefix>]`, all full-matched. Records, versions and the lockfile are registered document kinds (`LibraryRecord`, `LibraryVersion`, `AssetsLock`, all `0.1.0`), read through `migrate`.

**A version** holds:
- the existing descriptor verbatim (`doc`; a pydantic model is dumped with only the fields its author set);
- its files as `ContentRef`s;
- the asset-level `source`; `previous` (the head it follows) and `relicense` (`{by, reason}`, plus `covers` on a version with per-file statements) when set; `file_sources` (`{path: source}`, sha-pinned, an#345) when set;
- `derived_from` (pinned, namespaced);
- `affordances` + `analysers`;
- a `rights` cache;
- the `art` facet;
- `manifest_sha256`, the **version identity**: sha256 of the canonical JSON of `doc`, the files' hashes, `source`, the sorted `derived_from`, and `previous` / `relicense` when set. It is not a content key, so nothing caches on it as one.

A publish makes no new version when its manifest equals the head's, or when it is an unedited check-out of the head published back. A source declared on an earlier version carries forward only while the descriptor declares nothing new (nothing, or exactly what the head's descriptor declared). `expect_head` (`None` = must be new) guards against merging an unrelated asset into an existing id.

**Federation** (`an.library.federation`).
- `Library(name, mall, root)`.
- `search_path(package, extra=…, roots=…)` reads its own library, then `an`, then the extras.
- Reads take a library or a path. A bare id resolves in the first library that holds it; a namespaced id resolves only in its own library.
- Hits are namespaced when the search spans more than one library.
- Writes take one owning `Library`.

**Rights** (`an.library.rights`, `an.library.api.effective_rights`). Rights attach to the bytes and to the derivation chain. A version may only ever be **more** restrictive than what it inherits.
- *Contributors.* `version_sources` lists every source a version's rights depend on:
  - the asset-level source and the descriptor's own source. Both count: a declared `cc0` cannot mask a descriptor saying the art came from a film;
  - every per-part and per-plane source, read by `an.credits.collect_credits`, the walk `an credits` runs;
  - recursively, the version it follows (`previous`, set implicitly on every new version of an existing asset), so a later version cannot relabel the earlier one's art, even with new bytes;
  - recursively, every version it derives from. A parent that is not on the search path falls back to the rights recorded at publish;
  - the **floor** of every file: the strictest statement any library on this machine makes about its SHA-256 (`an.library.floor`). A version's statement about a file is its per-part `source` if that source pins the same digest (`AssetSource.sha256`), else the asset's own label (its asset-level and descriptor sources and lineage), else its relicence. The libraries read are the search path plus every package root under the data folder, every `<PKG>_HOME` root, and every root in the machine **registry of library roots** (`an.library.registry`, an#249), so the core library sees a genre's private bytes, and a library at a custom `--root` or under a since-changed environment still binds. The registry is JSON Lines, append-only (a torn line never swallows the next), at a path derived from the account's home as the OS records it (`~/.local/share/an/registry/library_roots.jsonl`), independent of `$HOME`, `XDG_DATA_HOME` and every `<PKG>_HOME`. Every `publish` registers its library's root before writing anything (an unwritable or unreadable registry refuses the write, `RegistryError`; an absent one is created with a `RegistryWarning` that says which case it is: new — no library discoverable now holds an asset — or lost — libraries hold assets, so it is rebuilt from discovery, registering them and re-remembering the statements their own indexes hold (an#307)), `reindex` re-registers, and a registered root that is gone is skipped. Beside it, the machine's **memory of statements** (`registry/statements/<aa>/<sha256>/`, one file per blob, root and asset, the latest version's statement) is written at every publish and read by every floor, so a library moved, renamed or deleted relaxes nothing. Libraries with injected stores (no root) are in neither record. Both feed the floor only — never a search path. Two libraries sharing a name (the default `cutan` and one at a registered custom root) can hold the same asset key; the floor keeps the stricter statement. `reindex` resolves lineage through its search path and then every library on the machine (`machine_libraries`; an#361: a promoted copy's parent in a genre library is read without being named), computes the new index in full, writes it over the old entry by entry and only then drops stale entries, so a crash never empties a floor. Each library keeps a derived `blob_rights` store (`sha256 -> {asset: statement}`), maintained by `publish` and rebuilt by `reindex`, so a floor is one lookup per library. The character factory stamps every part it draws `cc0` with its digest (`stamp_factory_parts(dir, paths)`, `paths` required: only the code that drew the bytes may stamp them), so shared factory parts stay free inside a carved character whatever the publish order, and stamps the descriptor too (`stamp_factory_descriptor`, pinned to its `source_svg`), so a fresh character has a source. A DiceBear head is pinned the same way: DiceBear's source with the head's digest on the head part, and with the drawing's on the descriptor (`stamp_generated_head`). A stamp speaks only for the bytes it pins: in `an credits` and in the library (one walk, `an.credits._part_credits`, given the files' digests) a part whose pinned digest no longer matches, or, under a generator's descriptor-level source (the factory's, DiceBear's), any file no stamp pins, is `unknown` unless a source a person wrote covers it; the `source_svg` is itemised in the floor by the descriptor's stamp when its digest matches, so a study publish never binds a fresh character's drawing. A **carried** asset-level source speaks only for the files unchanged since the version it was declared on: a file changed or added is recorded on the version as `unlabelled` (in the manifest) and is `unknown`, and later versions inherit that gap through `previous`. An asset-level `source=` covers the publishing version's own files; an earlier version's gap is answered by `publish(source=…, relabel={"by", "reason"})` (an#263): a first statement about bytes nobody labelled, recorded on the version, in its manifest and reasons, answering only the gaps of the asset's own `previous` chain (files recorded `unlabelled`, versions with no source) and nothing anyone stated (a licence of any class, a per-part source, a `derived_from` parent, another asset's floor statement). Each version pins its lineage (`lineage`: `{parent_ref: manifest}` for `previous` and every `derived_from`, in the manifest); a walk reads a parent only if it is still that version (`_resolve_lineage`), else the child's recorded rights stand in. A walk leaves out of the floor only the `unknown` statements of versions it read in full and verified (every link pinned and matched, or a `previous` inside the same library root), matched by library root and manifest, statement by statement before any merge (`version_sources(owner=…)`, `an.library.floor.library_origin`, `BlobFloor.each`); a `private` or `attribution` statement is always read, so an earlier version's own `unknown` does not bind past the label that answers it. Check-out writes the asset-level source into the copy in place of a generated descriptor source that owes nothing — the factory's stamp, a free DiceBear style (an#281); never one owing attribution — (restored on publish; compared semantically, `an.credits.same_source`), links an unedited project entry under its own key when one exists (an#271), recognises the one entry the lockfile pins to an EARLIER version of the asset asked for — by lineage (the requested version's pinned `previous` chain reaches the pinned manifest; a same-named library's asset or a downgrade is never a candidate) — and never copies beside it: unedited, it refuses naming `upgrade=True` (`--upgrade`), which removes only the files the earlier version named (a hidden draft stays) and moves the pin; edited, it refuses naming a publish or `--key … --overwrite`; two such entries refuse unless `key` names one; an explicit `key` always wins. One target-key function (`checkout._target`) serves `check_checkout`, `checkout` and `checkout_kit` (whose refusals name no `--key`; an#346), and records `library_origin.checked_out` (that descriptor source and the files' digests): while the descriptor holds that source, `an credits` lists a file edited or added since as UNVERIFIED, and a removed one as an UNVERIFIED asset (an#264). A generator's descriptor source with no digest (legacy DiceBear) pins nothing and speaks for no file. `new_character` records the digests its own stamps pin in the folder it created empty in that call (`registry/generated/`, `an.library.registry.record_generated`, not exported; the public stamping functions record nothing); a file a version itemises with the factory's own stamp AND whose digest is in that record (`an.library.api.factory_drew`) is not bound by another asset's `unknown` statement about it; away from the machine that drew it (or before the record existed), the record's silence is answered by re-deriving the bytes from the recipe the factory records in `metadata.factory` (`factory_recorded(digest, descriptor=, path=)` → the genre's `credits.factory_redraw` service; the replay, being the factory's drawing code, records what it draws, an#292) — a match at that path is proof, and carved bytes, an edited recipe or a DiceBear head prove nothing — the silence of an asset published before stamps — while `private` and `attribution` statements still bind. `an credits` lists the factory's and the sound synthesizer's work as made by `an` itself, not third-party.
- *Labels on an existing version* (an#307). A relabel of the head's UNCHANGED content (same descriptor, bytes and parents) mints no version: it is recorded on the head in the library's fourth store, `labels` (write-once, append-only: `library/labels/<asset_id>/<vNNN>/<id>.json`, the id a hash of the label's manifest, source, relabel and rights, so the same relabel with the same outcome writes nothing and an edited label is not counted). `version_labels(library, version)` reads them (only labels pinned to that version's manifest); every walk reads a version WITH its labels — each label's source contributes, and the earliest answers the version's and its chain's gaps — exactly as the relabel version it replaces would have; the version's floor statements are rebuilt when a label is written; `stored_rights` is the latest label's cached rights; `labelled_view` is what check-out writes into the copy, what `promote` copies and what a later publish carries. A relabel also answers (i) a file no person's source spoke for — the credits walk's placeholder for an unpinned part under a generated source, a stale or unconfirmed stamp, a file changed since a check-out (`an.credits.nobody_labelled`) — and (ii) another asset's `unknown` statement about a file the chain once held and the labelling version no longer holds, which before made two assets that shared byte-identical tool output block each other's labels forever. Never a `private` or `attribution` statement, and never another asset's statement about bytes the labelling version holds. When a publish stays `unknown`, `PublishResult.advice` (`unknown_advice`) says what answers each gap, from the remedy each contributor carries (`Contributor.remedy`: relabel, label the parent, label the other asset, or relicence).
- *Per-file statements* (an#345). `publish(license_parts={glob: source})` (CLI: repeatable `--license-part 'GLOB=LICENCE[,provider=…,author=…,url=…]'`, glob matched by `match_license_parts`: `*` stays in a folder, `**` crosses, case-exact, NFC; no match, two globs disagreeing on a path, or a near miss refuse) or `file_sources={path: source}` records a sha-pinned source per file in the version's optional `file_sources` (in the manifest when present; a version carrying it is written at version-document schema `0.2.0` so an older reader refuses it; carried to the next version while the bytes are unchanged, a changed file recorded `unlabelled`; compared by `_same_as_head`; passed by `promote`). They count toward the version's rights (contributors `file:<path>`, which check-out writes into the origin block, so `an credits` lists each with its provider) and never toward the label of the files nothing itemises (`version_sources(per_file=False)` in `_own_label_class`, at every depth). A version carrying them, or whose lineage does, states each blob by the never-relax rule (`_PerFileRule`): the strictest of its per-file statement (else that label), the same file's per-part source, the same bytes at its other paths, and what its lineage says about the bytes (the nearest holder's statement, or for new bytes the parent's own label); `publish` refuses a per-file statement looser than the part source or lineage unless relicensed, and a relicence on such a version records the digests it `covers`: a per-file statement stricter than it keeps binding, bytes the lineage labelled stricter per file are refused unless this publish labels them per file itself (a relicence frees only what it names), and for bytes it does not cover the lineage still speaks. The rule follows the lineage: a derivative of a version with per-file statements is under it too (written with `file_sources: {}` at schema `0.2.0`). An `an` older than this skips 0.2.0 versions when it reindexes, so their statements leave that library's index: never reindex a shared library root with an older `an`. Per-part `Attachment.source` itemisation keeps its old behaviour (extending the rule to it is an#357's question), so no stored statement moves on `reindex`.
- *Relaxing.* The only way to relax a version's rights is `publish(relicense={"by": …, "reason": …}, source=…)`: an explicit relicence, recorded on the version, in its manifest and in its reasons. It replaces everything the version would inherit, and it becomes its asset's statement about its bytes. Another asset holding the same bytes still meets every other library's stricter statement, so it must be relicensed itself.
- *Roll-up.* The most restrictive class wins: `private` > `unknown` > `attribution` > `free`. No source at all is `unknown`.
- *Recomputed, not trusted.* The stored `rights` block is a cache; `find(rights=…)`, `show` and `promote` recompute it and keep the stricter of the two.
- *Promote.* Copying to the core library refuses `private`/`unknown` without `allow_restricted=True`. It also refuses when the target already has an unrelated asset with that id (`as_id=`).
- *Known asymmetry.* A relicensed version's checked-out copy still carries the descriptor's and the parts' own sources, so `an credits` in the project can be stricter than the library. It errs toward the warning, never away from it.

**Affordances** (`an.library.affordances`, the seed of ADR 0002's `affordances(asset)`): `register_capability(name, description, remedy)` and `register_analyser(kind, version)`. An analyser receives the descriptor and `{path: ContentRef}` for the art present. `cutan.library` mirrors the compiler's own branch (a document that declares neither `kind: CharacterDescriptor` nor `parts` renders as the compiler's placeholder stand-in, so it affords only its rest view, and `publish` warns `PlaceholderRigWarning`):
- *For a `CharacterDescriptor`*, from the migrated descriptor and the art present:
  - `limbs.legs` / `limbs.arms`: the pairs `walk` resolves (`WALK_LEG_NAMES` / `WALK_ARM_NAMES`), both with art;
  - `swap.view`: `keys` are the rest view + the `view` keys with art; `swappable` says whether it can turn;
  - `face.mouth`: an overlay face with drawn visemes; `keys` are `rhubarb9` or `custom`.
- *For any other document*, the procedural `parts` rig as `_build_character_subtree` draws it.

`overrides` names the declared fields the derivation used (`rest_view`). Gait is not a capability: which walk methods apply is the matcher's answer (P7), derived from `limbs.legs`. `tests/test_library_parity.py` compiles every corpus scene plus a synthetic turnaround rig. It holds the analyser's limbs to the parts the compiler builds, `face.mouth` to the built `viseme` sets, and the turnaround keys to the built `view` sets. A snapshot made by an older analyser version is recomputed on read (`current_affordances`). No module in `an/library/` imports cut-out code at module level, and an AST test enforces it.

**Search** (`find`).
- AND across facets (`kind`, `style`, `family`, `origin`, `status`, `tags`, `art`, licence class), OR within one facet.
- `affords` terms (`cap` or `cap:key`) must all hold. An unregistered capability raises `LibraryError` and names the close ones.
- `near=True` adds the hits that miss only capabilities, each with `missing` and `remedies`.
- Counts per facet value come back with the hits.
- A damaged record or version is skipped with a `LibraryIndexWarning`, never failing the search.
- `near=True` also offers a factory character (role-tagged colours) curated for another style, `style:<wanted>`, whose remedy names the StylePack mechanism and says a recolour never changes a build; nothing else gets a style near miss (an#307).
- A `retired` asset (`retire`/`set_status`, recorded in the record's append-only `status_history`) is left out unless its status is asked for by name; its versions stay readable and its statements bind. Publishing into it is refused unless `status=` revives it.
- `vocabulary()` lists every facet value and capability, counted over what `find` offers by default — the same recomputed rights (`_rated_entries`), and retired assets only under `hidden`.
- The index is one keyword (`index=scan_index`).

**Check-out** (`an.library.checkout`, the v1 resolution strategy).
1. Resolve the reference.
2. Verify every stored path (clean and relative, with no collision under case or Unicode normalisation, and no file-and-folder clash), every blob (present, hash) and the manifest. Anything else is an `IntegrityError`: a library on the search path may not be one this machine wrote.
3. Write the descriptor and files into the project store's own layout. Each file must resolve inside the entry's folder, or nothing is written.
4. Write the asset-level source into a descriptor that has none (or only the factory's own stamp).
5. Record `metadata.library_origin`: the pin, the manifest, the recomputed rights, and every rights contributor the descriptor does not itself hold. `an credits` reads them as `<store>/<key>/via-library/<label>`, so the private-study warning fires for checked-out study material.
6. Pin `<store>/<key>` in `assets.lock.json` — the project mall's `library_lock` store (`ProjectLock`, in `an/stores/library_lock.py`, re-exported by `an.library.lock`).

Behaviour around it:
- Check-out is idempotent only for an intact copy of the same version. An edited file or descriptor is a fork, and a re-checkout refuses it without `overwrite=True` (`--overwrite`). An entry that is byte for byte the version but was never linked to it (the folder a publish just sent) is linked without `overwrite`.
- `verify_checkout` reports drift per pinned entry. The pin records provenance; it is a usable cache key only when `verify_checkout` finds no drift.
- `publish` strips exactly what check-out added.
- **The lockfile is the single source of truth for a pin** (an#240): it is written by the check-out, beside the manifest it verified. A scene's `AssetRef.library` restates it. `an validate` runs two registered checks (`finish` stage): `library_pins` — `check_pins(scene, lock)`, a `warning` for each `library:` that disagrees with the lockfile or names an entry it does not pin; and `library_checkouts` — `drift_findings`, an `info` for each pinned copy that is no longer its version (a fork). `validate_semantic(available_library_lock=…)` (`an validate` and `an iterate` pass it); an unreadable lockfile is a warning, never a traceback. The lockfile records no root (it is committed), so a pinned version is compared only when found with the pinned manifest; one not found, or found with another manifest (a same-named asset in another library), is an `info` "cannot verify", never drift. `render_project` runs the same pin check: a `LibraryPinWarning` per disagreement, a `LibraryPinError` under `strict_assets`. OS clutter (`.DS_Store`, hidden files, `Thumbs.db`: `an.stores._common.is_os_junk`) is skipped by publish, by drift and by the credits digests alike.

**IR.** `AssetRef.library: str | None` is a **pinned** reference (`[<library>:]<asset_id>@vNNN|sha256:<prefix>`; `@latest` is refused). It is omitted from every dump when unset (the `stage` serialiser), so no stored scene changed and `SCHEMA_VERSION` did not move. `tests/test_library_assetref.py` holds this over every committed scene. The compiler does not read the field yet; `ref` still names the project-store key.

**CLI.** `an library {publish,find,vocabulary,show,checkout,promote,retire}` (`an/library/cli.py`, mounted by `an.tools._dispatch_namespaces`). A refusal prints one sentence, naming the CLI flag beside the Python argument, and exits 1. A namespaced reference (`cutan:character.x@v001`) puts its library on the search path, so `checkout`, `show`, `promote` and `--derived-from` need no `--package` for it; with no `--package`, `--root` locates the library the reference names. `publish` of a folder inside a project prints the `checkout` line that links the project's copy.

**Not yet** (each lands at an existing seam):
- *Reference mode.* The compiler resolves `AssetRef.library` itself instead of reading a checked-out copy. This is design §7.3's `resolve=` keyword, declared only once that second strategy exists, after the renderer stages art through a store instead of `store._root`.
- `outdated`, `upgrade`, a `reindex` CLI, and aliases.
- ADR 0002's registry adopting the analyser (P7).
- Importing the 2026-09-30 session assets (P9).
- A `Library.scope` gate on `publish` into a shared library.
- An MCP surface over the same functions.
